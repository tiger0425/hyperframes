# 叙事弧线 —— 段骨架 + 帧数参数（阶段2 `storyboard` 的计划层内核）

> 本文件回答三件事：**弧线有哪几段、每段（每帧）负责什么、谁不许说什么、时长谁说了算**。
> 阶段名、产物路径、门禁命令以 [`_contract.md`](_contract.md) 为准（**§0.5 帧数是参数**、§2 五阶段与时间闭环、§3 已实测事实）。
> 视觉令牌（色 / 字 / 材料 / 颗粒）是 `visual-grammar.md` 的职责，这里一个字都不写。
> 下文所有数字来自 `projects/dsh-agent-teams-vox` 的**成片与其 `index.html`**，不是推测；该片恰好切成 12 帧，**12 是实例取值，不是规范**。

---

## 0 · 弧线是顺序，帧数是参数

```
钩子 → 问题 → 是什么 → 机制×N → 工具面 → 那个坑 → 演示×M → 边界与开工
```

**不许动的**：段的**顺序**、**每帧一个职责**。这两条是弧线的骨架，换主题也不变。
**每个项目自己定的**：每段占几帧、即总帧数 `{{FRAMES}}`。机制有几条就几帧，演示有几步就几帧。

```
{{FRAMES}} = 3（钩子 / 问题 / 是什么）
           + N_mech   （机制条数，一条一帧）
           + N_tools  （工具面，0 或 1 帧）
           + N_pitfall（那个坑，0 或 1 帧）
           + M_demo   （演示步数，一步一帧）
           + 1        （边界与开工）
```

本片实例：`3 + 3 + 1 + 1 + 3 + 1 = 12`。其中六个**论点帧**（钩子 / 问题 / 是什么 / 工具面 / 那个坑 / 边界与开工）**出现时各占且只占 1 帧**，无论主题多大都不许拆成两帧；中间两个可变段（机制、演示）**按条数展开**——这是唯一能伸缩的部分，也是帧数差异的全部来源。

> 常见错法：先定"我要做 12 帧"，然后把 4 个机制压进 3 帧。**帧数不够说明内容没分层**（把两个机制合并了），不是弧线的问题。合并机制帧的代价是其中一个机制永远讲不清；正确做法是让 `{{FRAMES}}` 涨到 13。

主张先立住：`BRIEF.md` 的 `message` 与 `STORYBOARD.md` frontmatter 的 `message` 必须是同一句，且**含一个具体名词**。本片实例：
「一个 DSH 会话可以变成一支**有名字、有共享任务板、消息不会丢**的团队——你现在就能开。」
第 3 帧要定义的东西（名字 / 任务板 / 消息）在主张里已各占一个词——这不是巧合，是"钩子必须被后面每一段兑现"的检查方式。

## 1 · 帧数怎么定（先分段，再数帧）

按顺序做四步，**不要先想帧数**：

1. **列内容清单**。这个主题真正承重的机制有几条（N_mech）？用户照做要几步（M_demo）？有没有"落到手上是什么"的一览（N_tools）？有没有一个反直觉的坑（N_pitfall）？
2. **段数 = 帧数**。清单条数直接决定 `{{FRAMES}}`，公式见 §0。机制 4 条就 4 帧，演示 5 步就 5 帧。
3. **检查每帧是否只装一件事**。任一帧装着两件事 → 拆帧（`{{FRAMES}}` +1），不要加长这一帧的时长来硬吃。
4. **查总长**。用 §6 的折算规则（汉字数 / 4.6 + 2.7s 呼吸）估总时长，与 `BRIEF.md` 的 `length` 对一下；然后按 +20~30% 留余量。

参考区间（来自 [`_contract.md`](_contract.md) §0.5，是**起步估算**，不是判据）：

| 内容规模 | 帧数 `{{FRAMES}}` | 形状 |
|---|---|---|
| 单个概念 / motion graphic | 4–6 | 钩子 → 概念 → 一两个例证 → 收尾（无机制段、无演示段） |
| 单一主题教学片（本片实例） | 12 上下 | 前后 6 帧 + 3 机制各 1 帧 + 3 步演示各 1 帧 |
| 多机制产品讲解 | 14–20 | 机制与演示按实际条数展开，**别硬塞进 3** |

段的取舍判据（工具面与坑段可省，另外两段不可省）：

- **工具面（0–1 帧）**：内容里存在一张"落到模型/用户手上是什么"的清单（工具、参数、入口）才要；纯概念主题直接省掉。
- **那个坑（0–1 帧）**：有反直觉点（文档写了"注意"、有已知限制、有踩过的事故）才要。没有就别硬凑"注意事项"帧——凑出来的一定是套话。
- **边界与开工**这一帧**不能省**：诚实纪律要求结尾必须点到已知限制（§8）。内容确实没有已知限制时，也要用一帧说清适用范围。

## 2 · 段骨架表（照填：段是固定的，帧数是参数）

`transition_in` 与 `poster` 在 `STORYBOARD.md` 里**每帧必填**（阶段2 出口判据之一），它们不是装饰：

- `transition_in` —— 这一帧的**入场接缝**：`cut` / `crossfade`。留空 = Studio 拿不到接缝意图。
- `poster` —— **秒数**，从本帧自己的 0 秒算起，seek 到这一帧的"代表画"（入场动画已走完、画面最满、还没开始收）。

**表 A · 段骨架**（新主题照填这一张）

| 段 | 帧数（参数） | 该段只负责 | 该段禁报名 |
|---|---|---|---|
| 钩子 | 1 | 1 个主张 + 1 个限定（"不是比喻"式）；≤3 个视觉件 | 任何解释、铺垫、机制名、列表、"今天我们来聊聊" |
| 问题 | 1 | 3 个痛点，每个一行，**用观众自己的语言** | **任何产品名词**（本片实测：整帧不含"Agent Teams"）、任何解决方案暗示 |
| 是什么 | 1 | 命名（含"是 X 不是 Y"）+ 组成拆解 + 角色名；一次性讲完定位 | 怎么用（属演示段）、机制细节（属机制段）、命令、安装步骤 |
| 机制 ×N_mech | **N_mech**（一条一帧） | 每帧 = 一个机制 = **一个可画的动作** + 一个静态落点 | 两件事一帧、功能列表、"它支持 A、B、C、D"、把后果提前说完 |
| 工具面 | 0 或 1 | 总数 + 分类 + 每类一句**中文能力名** + 权限差 | 逐工具演示、参数细节、把工具名当能力名（只念 `spawn_teammate` = 没讲） |
| 那个坑 | 0 或 1 | 1 个反直觉点 + 触发它的具体事件序列 + 谁必须兜住 | 引入新机制、操作演示、收尾语、把坑缩小成一句轻描淡写 |
| 演示 ×M_demo | **M_demo**（一步一帧） | 每帧 = 一个**用户能照做的动作**（动词），单一动作 | 复述机制、超出已介绍过的界面、语法 / 配置 / 命令行参数 |
| 边界与开工 | 1 | 3–4 条已知限制 + 最小可执行路径 + 回扣主张；帧尾留一拍 | 任何新能力、"稳定 / 生产可用"暗示、加长版"感谢观看"空收尾 |

**表 B · 每段的接缝与运动倾向**

| 段 | `transition_in` 倾向 | `poster` 取值 | `motion`（1–2 个） |
|---|---|---|---|
| 钩子 | `cut`（冷开场硬切） | 入场动画结束 `+0.5s` | 大字砸落类 + 弹簧入场 |
| 问题 | `crossfade` | 全部卡片到位后 `+1s` | 手绘连线 + 弹簧入场 |
| 是什么 | `crossfade` | 组成件归位后 `+1s` | 纵深散落归位 + 弹簧入场 |
| 机制帧 | 段首 `cut`，段内 `crossfade` | 该机制画完后 `+1s` | 按机制选 1 个主动效 + 1 个入场收尾 |
| 工具面 | `cut`（换话题） | 分组落定后 `+1s` | 中心炸开成组 + 弹簧入场 |
| 那个坑 | `crossfade` | 警告条滑入后 `+1s` | 标记笔触 + 弹簧入场 |
| 演示帧 | 段首 `cut`，段内 `crossfade`；画面主体整个换掉的帧用 `cut` | 该步动作完成后 `+1s` | 打字机 / 光标类 + 布局展开类 |
| 边界与开工 | `crossfade` | 命令自绘完成、主标题回归后 | 逐条落下 + 手绘自绘 |

**`cut` 的判据不是"隔几次来一下"，而是"这里必须让观众重新坐直"**：冷开场、机制段段首、工具面（换话题）、演示段段首、责任落点。同一条论证往下走（问题→是什么、机制之间、坑的展开、收尾）一律 `crossfade`。本片实例：12 帧里 `cut` 5 次、`crossfade` 7 次，落点与上述位置逐一对上。

`poster` 的取值法：**最后一个元素到位之后 +1 秒**。没有"中部保留期"的短帧（如钩子帧）就贴准入画结束——本片钩子帧 `poster: 3s`，入画约 2.5s 完成。全部 `poster` 都必须小于该帧时长。

## 3 · 机制段模板：一个机制 = 一个可画的动作

**判断标准：这个机制能不能用一个动词短语说完、并且画出来？** 不能 = 你把两个机制塞进了一帧（→ 拆帧）。

单个机制帧的三件套：

| 件 | 要求 | 本片实例（3 个机制） |
|---|---|---|
| 主体 | 一个可视对象（表格 / 卡片 / 路径 / 面板），不是抽象名词 | 花名册 = 一列行；信箱 = 消息卡 + 磁盘；任务板 = 一张任务卡 |
| 动作 | **一个**动词短语，施工时能直接翻成 GSAP 时间线 | 逐行落下 + 状态芯片；先落盘、再三路投递；展开出字段 + 旧版本驳回 |
| 落点 | 一个静态可读的结论画面（= `poster` 那一秒） | 名册落满 / 三路标好 / 被红框驳回 |

机制帧的**次序**同样承载信息，按"从静到动、从人到事"排：

```
机制① 身份（谁在场）→ 机制② 通道（话怎么到）→ 机制③ 契约（活怎么认领与改）
```

这是本片三条机制的天然顺序，不是通用规则：**按"对象 → 关系 → 约束"排**即可（先出现的东西，后出现的关系，最后是规则）。4 条机制时同理——前两条讲对象与关系，后两条讲约束与例外，别把两条"约束"拆到首尾。

机制帧的两条禁令：

- **机制帧只埋限定，不给后果**。本片第 6 帧只写"写范围只是提醒，不拦人"，其后果（Bash / 格式化工具 / 代码生成器都能绕过、所以 Lead 必须自己看 diff）留到"那个坑"帧。机制帧提前把后果说完，坑帧就没有存在理由了。
- **机制帧不许变成功能列表**。列表不可画 = 这一帧没有画面，只有旁白。

## 4 · 演示段模板：一步一帧，动词必须可照做

```
演示① 发起 → 演示② 观察 → 演示③ 担责
```

`M_demo` 由**用户真正要做几步**决定；三步是本片实例（说一句话建队 / 在面板上盯着 / 收口验收）。每帧**只准一个动作**，而且必须是用户真能照做的那一个：

| 步 | 这一帧的动词 | 必须回答 | 本片实例 |
|---|---|---|---|
| ① | 说 / 按 | 说什么、按哪里、系统接着做了什么 | 输入框逐字打出指令 → 回车 → roster 冒出两行 |
| ② | 看 / 点 | 入口在哪、有哪几块、每块能看出什么 | 标题栏 Team 入口 → 面板两栏 → 点进 teammate 会话 |
| ③ | 验收 | 要确认几件事、最后一件是谁的责任 | 三张检查卡盖章，第三张"diff 必须自己看" |

三条硬约束：

1. **不许超出已介绍过的界面**。演示帧出现的每个控件，必须在"是什么"段或本段前一步出现过；凭空冒出的 UI = 观众第一次见，学不会。
2. **模拟界面必须自证是模拟**（本片在 `BRIEF.md` 的 Customizations 里写死："字段与中文文案取自真实客户端插件，不使用真实截图"）。字段名必须来自真实产物，不许编。
3. **最后一步落到责任动作，不落到"完成啦"**。演示段的价值是让观众知道"我该干什么"，而不是"这个功能很棒"。

演示步数多于 3 时，最后一步必须仍是责任动作（验收 / 复核 / 回滚），前面多出来的步骤都是"做"。

## 5 · 跨段三条禁令

1. **无新概念**：任何名词必须在它首次出现的那一帧被解释，之后可自由复用；不允许在"那个坑"段冒出一个前文没定义的东西。
2. **不预告**：禁止"接下来我们看…""稍后会讲…"——旁白的秒数买不起这句废话，弧线本身负责衔接。
3. **同一个论点只准说一遍**：允许**回声**（坑帧重复机制帧的"写范围只是提示"，因为那时才给后果），不允许**复述**（同样的详略把同一件事再说一次）。判断法：删掉后一帧的这句话，观众会缺什么？答不出就删。

配额检查放在扫一遍全片时做：**每一帧的旁白能不能压缩成一句"这一帧负责……"**？两帧压缩出同一句，就是复述。

## 6 · 时长由旁白决定（时间闭环对计划层的三个约束）

> 完整流程见 [`_contract.md`](_contract.md) §2「时间闭环」。这里只写它**对计划层的要求**。

**故事板里的 `duration` 是意图值，不是成片时长。** 它只有三个合法用途：

1. 给单帧一个**内容密度预算**（15s 的帧不要塞 40s 的信息）；
2. 给 `poster` 一个量级参考；
3. 让 `STORYBOARD.md` 在 Studio 联系表上先有形状。

**它有三种非法用法**：当成剪辑时长的承诺、当成旁白字数的上限、在阶段4 之后还留在任何产物里冒充真值。阶段4（`voice`）拿到真实 wav 秒数后，**槽位 = 旁白 + 呼吸**必须重算，重算结果回写 `index.html` 与 `BRIEF.md` 运行中记录。

### 本片实测：意图 vs 槽位（`{{FRAMES}}` = 12 的实例数据）

| 帧 | 段 | 意图 duration | 实测槽位 | 旁白时长 | Δ（槽位−意图） | 余量（槽位−旁白） |
|---|---|---|---|---|---|---|
| 1 | 钩子 | 9.0 | 11.0 | 8.27 | +2.0 | 2.73 |
| 2 | 问题 | 15.0 | 18.8 | 16.13 | +3.8 | 2.67 |
| 3 | 是什么 | 15.0 | 20.0 | 17.29 | +5.0 | 2.71 |
| 4 | 机制① 身份 | 15.0 | 18.8 | 16.13 | +3.8 | 2.67 |
| 5 | 机制② 通道 | 18.0 | 24.9 | 22.17 | +6.9 | 2.73 |
| 6 | 机制③ 契约 | 18.0 | 21.3 | 18.61 | +3.3 | 2.69 |
| 7 | 工具面 | 17.0 | 19.7 | 17.01 | +2.7 | 2.69 |
| 8 | 那个坑 | 17.0 | 24.8 | 22.12 | **+7.8** | 2.68 |
| 9 | 演示① 发起 | 18.0 | 20.0 | 17.29 | +2.0 | 2.71 |
| 10 | 演示② 观察 | 19.0 | 24.1 | 21.40 | +5.1 | 2.70 |
| 11 | 演示③ 担责 | 15.0 | 17.6 | 14.93 | +2.6 | 2.67 |
| 12 | 边界与开工 | 19.0 | 23.1 | 18.76 | +4.1 | **4.34**（尾部定格） |
| — | **合计** | **195.0**（3m15s） | **244.1** | **210.09** | **+49.1（+25.2%）** | — |

从这张表里长出四条可直接用的规则：

1. **计划会系统性偏短**。本片 12 帧**全部**上涨，没有一帧缩短，总计 +25.2%。所以 `BRIEF.md` 的长度预算要按 **+20~30% 留余量**，或者直接把 `length` 写成 `content-driven`（本片实例），不要报一个准数然后被打脸。帧数伸缩同样用它：帧数估少了，涨的不只是时长，是**段**。
2. **余量是常数，不是拍脑袋**：槽位 − 旁白 ≈ **2.70s**（本片逐帧 2.67–2.73，极稳），即帧首旁白 0.3s 入点 + 帧尾约 2.4s 定格。**末帧额外多留**（本片 +4.34s），因为结尾要停一拍。所以计划期可按

   ```
   意图秒数 ≈ 汉字数 / 4.6 + 2.7        （末帧再 +1.6）
   ```

   反算。中文旁白实测语速 **≈4.6 汉字/秒**（讲解向、略快）；英文工具名密集的帧（本片第 7 帧，160 个字符里近 100 个是英文与符号）掉到 3.6 汉字/秒，**别用那一帧反算总长**。
3. **涨得最凶的是"那个坑"和"通道"**：本片第 8 帧 +7.8s、第 5 帧 +6.9s。规律是**要讲清一个反直觉点或一条投递链路，字数天然压不住**。分配意图时长时，这两类帧给最大余量；钩子帧给最小（本片 9s → 11.0s，是涨得最少的一帧）。
4. **四处时长必须同时等于槽位**（帧根 + 帧内三个 `.clip` 层），且 `NN-slug.motion.json` 里的 `duration_s` 也要等于真值。`sync-frame-durations` 现**同时覆盖** `index.html`、帧根与侧车 `duration_s`，侧车漂移会被自动写回；写侧车时仍建议直接写槽位真值。
   （历史背景：早期版本只同步 `index.html` 与帧根，本片 12/12 侧车因此停在**意图值**——如 `05-mailbox.motion.json` 写 `duration_s: 18` 而槽位是 24.9；该实例已由 `sync-frame-durations` 回写修复，见 `_contract.md` §2/§3。）

> ⚠ **回写漂移的历史实例（已闭环）**：本片 `BRIEF.md` 的「运行中记录」与 `SCRIPT.md` 头部曾写着旁白重建**之前**的数字（`实际时长 3m15s（12 帧 / 195s）`、`总语音时长 153.88s`），而成片 `index.html` 根 `data-duration="244.1"`、12 条 `voice_0NN.wav` 合计 210.09s。**两份数字不一致时，一律以成片与 `index.html` 为准**，并把运行中记录回写成真值——`_contract.md` §2 第 4 步存在的理由就是这个。本项目三份档案**已按此回写为 244.1s / 210.09s**，此处保留为教学实例。

## 7 · 术语纪律（本片最硬的一条）

`BRIEF.md` 的 Notes 里写死：面向小白时，**未解释的 CAS、幂等、exactly-once、进程单例等术语禁止出现**；出现即须当场用一句人话说明。

四条执行规则：

1. **能换就换**。实现术语换成**能力名**——本片"工具面"帧把九个工具讲成"建人 / 传话 / 看和等 / 任务板的四个动作"，一句实现语言都没有。
2. **工具名保留英文，但必须配中文类名**。`spawn_teammate` 单独念出来对小白等于噪音；`第一类建人：spawn_teammate` 才成立。念法也要写进 `SCRIPT.md` 的 `Delivery`（本片："工具名念英文，其余中文"）。
3. **首次出现当场配解释，视觉上不许降级**：解释文字字号 **不小于正文的 0.8 倍**。塞进脚注 / 角标 / 缩小灰字 = 违反（角标只允许承载"实验性"这类**状态标注**，不承载定义）。
4. **旁白与画面用同一套词**。本片名册帧的状态芯片（运行中 / 空闲 / 未运行 / 准备中 / 失败）与旁白逐字同源，"用真实中文文案"是硬要求——画面里出现旁白没解释的英文状态词，同样是术语违规。

自检法：把任一帧的旁白单独念给一个没用过该产品的人听。**如果他需要反问"XX 是什么"，这一帧就不合格。**

## 8 · 诚实纪律

1. **结尾必须点到已知限制**，而且要在**旁白里**说，不能只挂在角标上。本片结尾帧口播四条：实验性不承诺稳定、成员共用同一目录改动立即可见、没有文件锁、只在单进程里成立。
2. **实验性不许说成稳定能力**。首次介绍该能力的那一帧（本片第 3 帧）就固定挂一枚"experimental——不承诺稳定"的角标，坑帧再点一次后果，结尾帧正式收口。三处口径必须一致——不许前面说"官方插件"、结尾才说"实验性"。
3. **坑要讲透，不许软化**。本片坑帧给的是完整链路：负责人永不自动释放 → 成员空闲 / 被中断 / 进程退出 / 失败都不影响 → 所以必须靠人收口；并补一条同类坑（写范围只是提示，Bash / 格式化工具 / 代码生成器都能绕过）。
4. **把责任交回观众**：结尾的责任动作必须是"你自己看 diff"这种**用户动作**，不是"我们会保证"这种**产品承诺**。

反面清单：`"已经完全可用"`、`"生产就绪"`、`"无缝"`、`"自动帮你搞定"`、把限制写在视频描述里而口播不提——出现任一条即不合规。

## 9 · `motion` 字段与动效名

- 每帧在 `STORYBOARD.md` 里声明 **1–2 个动效规则名**（字段名 `motion`，逗号分隔）。它是**施工指令**：阶段5 的作者按名字实现，不按自己的审美临时挑缓动。
- 施工完成后落到每帧一个侧车 **`compositions/frames/NN-slug.motion.json`**（本项目 12/12 齐全，即该项目帧数），字段：

```json
{
  "scene": "frame-05-mailbox",
  "duration_s": 24.9,          // ← 时间闭环后写槽位真值，不要留意图值
  "rules": ["spring-pop-entrance", "svg-path-draw", "waterfall-entry", "nudge-curve"],
  "entry": { "vector": "up +107px/s at first frame (message card pops from nothing)", "from_rest": true },
  "exit":  { "vector": "down +46px/s at last frame (red veto stamp landing)", "still_moving": true }
}
```

- `entry` / `exit` 是**给下一帧的移交说明**：出画向量决定入画向量（见 `motion-doctrine`）。任何一帧写 `still_moving: true`，接缝就必须按运动方向匹配，不能硬切。

**命名纪律**：只用已有规则名，不发明新名。本片（`{{FRAMES}}` = 12）实际用到的 13 个名字：

| 名字 | 画的是什么 |
|---|---|
| `kinetic-beat-slam` | 大字逐词砸落（钩子） |
| `spring-pop-entrance` | 元素弹簧弹入（通用入场，出现最多） |
| `svg-path-draw` | 手绘线 / 对勾按 `getTotalLength()` 逐笔画出 |
| `depth-scatter-assemble` | 3D 纵深散落 → 归位（讲"由几块拼成"） |
| `waterfall-entry` | 行 / 条逐条甩入（列表、限制清单） |
| `vox-annotate` | 手绘圈注 + 细线拉到注释 |
| `anchored-layout-expand` | 一张卡从一个锚点展开成完整卡片（面板 / 任务卡） |
| `counting-dynamic-scale` | 数字计数递增 + 随之缩放（版本号） |
| `center-outward-expansion` | 从中心炸开成组（矩阵式一览，如工具面） |
| `css-marker-patterns` | 圈 / 划 / 框等标记笔触（坑帧的粗红圈） |
| `discrete-text-sequence` | 逐字打字机（用户输入的指令） |
| `cursor-click-ripple` | 光标移动 → 按下 → 涟漪 |
| `nudge-curve` | 慢-快-慢三段式整体位移（收口前的轻推） |

**选名规则**：先定"这一帧的落点画面是什么"，再挑能到达它的 1 个主动效；第二个名字只允许是**入场收尾类**（`spring-pop-entrance` 是最常用的第二名）。两个都是大动作 = 这一帧没有主角。
